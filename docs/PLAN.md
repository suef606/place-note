## 2. 한 장 기획서 (08차시 A2 PRD)

1. **문제**: 친구가 카카오맵으로 공유한 장소를 열어 확인한 뒤 네이버지도에서 다시 검색해 저장해야 해서 번거롭고, 시간이 지나면 누가 추천했는지, 왜 저장했는지(가고 싶어서인지, 가 봤더니 좋았는지) 알 수 없다.
2. **누가·언제**: 나 + 카카오맵·구글지도를 쓰는 친구에게 장소를 자주 받는, 네이버지도를 주로 쓰는 사람 / 친구가 카톡으로 장소를 보냈을 때, 그 장소에 가 보고 난 뒤.
3. **MVP 3**
   - ① 카카오맵·구글지도·네이버지도 장소 링크만 붙여 넣으면 장소 이름 추출 → 버튼 한 번으로 네이버지도 검색
   - ② 장소 저장: 그룹(친구·회사·데이트·가족 등), 추천한 사람, 상태(가고 싶음/가 봤음)
   - ③ 가 본 뒤 후기: 간 날짜, 같이 간 사람, 평가, 후기
   - 안 할 것(그때 기준): 사진 첨부, 친구와 그룹 공유, 지도에 핀 찍기
4. **화면(위 → 아래)**: 링크 붙여넣기 + 네이버지도 열기 → 그룹·약속 고르고 바로 저장 → 자세히 저장 → 그룹·상태별 목록 → 장소별 후기
5. **저장할 데이터**: 아래 5장 참고
6. **성공 기준(제안)**: 친구에게 받은 장소를 일주일에 세 번 이 페이지로 저장하면 성공

## 5. 데이터 구조 (Supabase)

**places (장소)**

| 칸 | 뜻 |
|---|---|
| id, user_id, created_at | 자동 (user_id = 주인) |
| name | 장소 이름 |
| address | 지점·위치 |
| source_url | 친구가 보낸 원래 링크 |
| naver_url | 네이버지도 링크 (네이버 링크면 장소 페이지, 아니면 검색) |
| recommender | 추천한 사람 |
| status | `want` 가고 싶음 / `been` 가 봤음 |
| folder | 그룹 (친구·회사·데이트·가족·직접 지은 이름) |
| memo | 한 줄 메모 |
| agreed_on | 약속 잡은 날 (기본: 저장한 날) |
| plan_date, plan_time | 갈 날짜·시간 (비면 미정) |
| plan_with | 같이 갈 사람 (비면 미정) |

**reviews (후기, 한 장소에 여러 개)**

| 칸 | 뜻 |
|---|---|
| id, user_id, place_id, created_at | 자동 |
| visited_on | 간 날짜 |
| with_whom | 같이 간 사람 |
| rating | 별점 1~5 |
| tags | 태그 (주차 가능, 웨이팅 있음 등) |
| must_eat | 꼭 먹을 메뉴 |
| comment | 후기·특이점 |

**보안(RLS)**: 두 테이블 모두 RLS 켬. 로그인한 사람만, `auth.uid() = user_id`인 **자기 데이터만** 읽기·넣기·고치기·지우기. 로그인 안 한 사람(anon)은 권한 없음.

## 6. 아직 실행해야 할 SQL

Supabase **SQL Editor**에서 창을 비우고 실행 (여러 번 실행해도 안전):

```sql
alter table public.places add column if not exists agreed_on date default current_date;
alter table public.places add column if not exists plan_date date;
alter table public.places add column if not exists plan_time time;
alter table public.places add column if not exists plan_with text check (char_length(plan_with) <= 100);
alter table public.reviews add column if not exists tags text[] not null default '{}';
alter table public.reviews add column if not exists must_eat text check (char_length(must_eat) <= 200);
```

⚠️ 처음 테이블을 만든 SQL(맨 위에 `drop table`이 있는 것)은 **다시 실행하지 않기** — 저장한 데이터가 지워져요.

## 7. 할 수 없는 것과 주의할 점

- **카톡 채팅방 이름·대화 속 날짜**: 카톡이 공유할 때 넘기는 건 링크와 글뿐이라 받아 올 수 없음. 대신 '3번 이상 함께한 사람' 추천 + 자동완성 + '약속 잡은 날' 자동 입력으로 보완.
- **카카오맵 이름 읽기는 비공식 방법**: 카카오맵 페이지가 내부에서 쓰는 정보 주소를 사용. 카카오가 바꾸면 갑자기 안 될 수 있음. 실패하면 빨간 문구 끝 `[ ... ]`에 진단 정보가 나옴. 정식 서비스로 키울 때는 공식 API로 바꾸고 이용약관 확인.
- **아이폰**: 공유 목록에 안 뜸 → 링크 복사 후 📋 붙여넣기.
- **Vercel Hobby는 개인·비상업용**: 돈을 받는 서비스가 되면 유료 요금제로.
- **publishable 키**는 페이지에 있어도 됨(RLS가 지켜 줌). **secret 키·service_role 키는 절대 코드에 넣지 않기.**
- **저장소가 Public**: 이 문서와 코드가 누구에게나 보임. 앱 출시를 생각하면 Private로 바꾸는 것도 고려 (Vercel 연결은 그대로 유지 가능한지 확인 후 진행).

- **네이버지도 저장 탭**: 저장 리스트를 친구에게 공유 가능.

## 10. 수정·배포 방법 (메모)

1. 내 폴더의 파일을 고친다 (또는 Claude가 고쳐 폴더에 저장).
2. GitHub `place-note` → **Add file → Upload files** → 바뀐 파일 끌어다 놓기 → 커밋.
3. 1분 뒤 사이트에서 **Ctrl + Shift + R**.
4. Vercel 프로젝트 화면의 **Source 커밋 메시지**와 **Ready**로 최신 반영 확인.
5. 잘못되면 Vercel **Instant Rollback**으로 이전 버전 되돌리기.
6. 테이블 칸을 바꿀 때는 **SQL을 먼저** 실행하고 파일을 올린다.
